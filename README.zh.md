# SSH 云服务器

在 DSH Desktop 的右侧栏管理 SSH 服务器：自定义名称、保存私钥路径或密码、选择显示 IPv4 / IPv6 / 双栈。点击「连接」后在本页就地显示连接状态并建立 SSH 终端，同时把任务提示自动复制到剪贴板，由你决定粘贴到哪里。连接成功后，可在主机卡片里按需展开「远程文件」。

[English](./README.md) | 简体中文

仓库：<https://github.com/Laivikto/dsh-ssh-servers>

## 功能

- **原生私钥文件选择器** — 不用手动粘贴路径。点「浏览…」选出目录，插件列出里面的文件，点一下自动填入。
- **实时连接健康** — 每 30 秒检测一次，`✓ 已连接` / `✗ 未响应` 直接显示在服务器卡片上。
- **原聊天重连** — 先回到上次的聊天，再点「在原聊天中重连」。连接恢复后可继续使用该聊天的 SSH 工具。
- **记住右栏宽度** — 在 SSH 服务面板打开时拖动右栏边界，下次打开面板自动恢复宽度。窄窗口和全屏继续由宿主调整。
- **连接诊断** — 认证、DNS、端口、网络和主机指纹错误会显示具体的检查提示。
- **就地状态切换** — 连接成功后停留在本页，按钮变为「打开新聊天」，由你决定何时进入。
- **提示词自动复制** — 连接成功即把任务提示写入系统剪贴板，可粘贴到任意聊天或编辑器；不占用输入框。
- **远端文件浏览（已并入主机卡片）** — 不再需要切换到另一个标签页。连接后可在卡片内展开远程文件。每台主机记住上次打开的目录，连接断开时自动收起。走独立的 `ssh` 执行通道，浏览时不会往你的终端里输入命令。
- **统一 30 秒心跳** — 主机连接状态与文件区块共用同一轮探测；窗口在后台时自动跳过，回前台后立即追上。
- **SFTP 上传** — 选文件后先检查同名，再决定上传、改名或覆盖。单文件最多 32 MB。若上传中断，可核对目标文件是否存在以及大小是否一致。
- **巡检快照** — 对已连接的 Linux 主机采集根分区、内存、负载和选填的 systemd 服务状态，保存最近两次以便对比和复制。
- **IPv4 / IPv6 / 双栈显示** — 保存后自动解析并展示地址，默认打码，可用眼睛图标切换明文。
- **主机密钥策略** — 首次自动信任（TOFU）或依赖 `known_hosts` 的严格校验。
- **界面与报错双语** — 跟随界面语言切换中英文；连后端的错误提示（认证失败、目录不可读、文件过大等）也会按当前语言返回。

## 安装

插件通过 npm 分发，两种装法任选其一。

### 方式一：DSH Desktop 图形界面

1. 打开 DSH Desktop
2. 进入 **设置 → 插件**（Plugins）
3. 点 **添加插件 / Add plugin**
4. 输入包名 `@laivikto/dsh-ssh-servers`
5. 确认安装，重启 DSH
6. 右侧栏出现「SSH 云服务器」标签

### 方式二：命令行（复制即用）

```bash
dsh plugin add @laivikto/dsh-ssh-servers
```

如果有多套 profile，指定其中一个：

```bash
dsh --profile desktop plugin add @laivikto/dsh-ssh-servers
```

装完重启 DSH。以后升级用：

```bash
dsh plugin update
```

> profile 依赖和 `dsh.profile.bundles` 的注册由插件管理器自动写入，不要手动跑 `pnpm` 或改 `cordis.patch.yml`。

### 卸载

在 **设置 → 插件** 中禁用或移除该插件即可。

## 使用

1. 在聊天右上角的 SSH 图标，或右侧栏的标签页 / 向导入口中打开「SSH 云服务器」面板。
2. 点击「添加服务器」，填写名称、地址、端口、用户名和认证方式。
   - **私钥方式**：点「浏览…」选择目录，或直接粘贴绝对路径。插件把路径交给系统 OpenSSH；不会复制私钥内容。
   - **密码方式**：密码保存在本机 DSH 凭据库，点击连接时只写入终端，不进入聊天。
3. 选择地址显示（IPv4 / IPv6 / 双栈）和主机密钥策略，保存。
4. 点击「连接」。卡片就地显示 `✓ 已连接`，按钮变为「打开新聊天」，同时**检查提示已复制到剪贴板**。
5. 点「复制提示」可随时重新复制；点「打开新聊天」只是打开会话，粘贴提示后自行发送。

## 界面状态

| 状态 | 含义 | 按钮 |
| --- | --- | --- |
| `待配置` | 尚未保存凭据 | 连接（禁用） |
| `凭据就绪` | 凭据已保存，未连接 | 连接 |
| `✓ 已连接` | SSH 链路正常（30 秒轮询确认） | 打开新聊天 |
| `✗ 未响应` | 链路已断或终端已退出 | 打开新聊天 |

> 健康检测是非侵入式的：只读取终端进程状态和屏幕断线特征，**不会向你的终端写入任何命令**。

## 安全边界

- 密码与私钥口令保存在 DSH 的本地凭据库中，不以明文写入配置或聊天记录，也不会作为工具参数发送给模型。
- 凭据记录与目标 `host + port + username + authMode` 绑定。即使本机其他程序调用连接接口，也不能把已保存的密码改发到另一个**字面目标**；DNS 解析变化或首次连接的主机密钥仍需你自行验证。
- 连接使用空 SSH 配置（`-F NUL` / `/dev/null`），并禁用 `ProxyCommand`、`ProxyJump`、`LocalCommand`、`RemoteCommand` 等配置项，避免 `~/.ssh/config` 改写实际目标或在连接阶段执行额外命令。
- 私钥文件只由本机 `ssh` 进程通过 `-i` 读取。插件不解密、不复制、不上传私钥；私钥路径通过终端环境变量传入，命令回显不显示路径，但 OpenSSH 调试输出或终端历史仍可能包含路径。私钥**内容**不会发送给模型。
- 私钥目录列举接口只返回文件名、路径、大小和「是否疑似私钥」，**不读取私钥内容**。远端文件接口（`fs-list` / `fs-preview` / `fs-download`）会把远端文件内容返回到本地面板，但仅限「你已保存凭据的主机 + 绝对路径」，且只能从受信任的 DSH 页面调用（loopback 加 Origin / `Sec-Fetch-Site` 校验），内容不会进入模型上下文。所有路径都拒绝换行与空字节注入，并在抵达远端 shell 前做单引号转义。
- 文件通道遵守你设置的主机密钥策略：**严格模式**会传 `StrictHostKeyChecking=yes`，未知主机密钥直接失败，而不是被静默接受。
- 文件通道用解析出的 `ssh` 绝对路径并以 `shell: false` 启动；Windows 上终端里启动 ssh 同样使用 `ssh.exe` 的绝对路径（cmd 会优先在当前目录查找命令），当前目录里被放置伪装的 `ssh.exe` 也无法劫持。
- 修改主机的连接目标（地址、端口、用户名、认证方式）或删除主机时，该主机现有的 SSH 连接会立即失效，需要重新连接，避免界面显示新地址而命令仍发往旧服务器。
- 每条通过插件执行的远程命令都要在界面中确认。`ssh_terminal_run` 的确认按钮只授权当前这一条命令。
- **插件不能限制聊天里的其他本地工具**：如果该聊天同时拥有本机可执行工具，模型仍可能尝试本地命令。建立连接后，插件会尝试为该 Agent 安装工具限制，只允许 `ssh_terminal_read`、`ssh_terminal_run`、联网查证、`skill` 和用户确认；若宿主版本不支持该限制，则只剩提示词约束。私钥文件读取权限最终由你的 DSH 权限模式和操作系统用户决定。
- 首次自动信任（TOFU）无法在第一次连接前验证服务器身份；严格模式要求本机 `known_hosts` 已有正确记录，否则连接失败。
- 本机 DSH 凭据库文件对当前操作系统用户可读。插件不向模型提供该路径，但同一用户运行的本地工具仍可能读到它；这不是操作系统钥匙串级别的隔离。
- 远端命令输出会进入聊天上下文，可能包含服务器信息。不要在不信任的服务器上运行会输出秘密的命令。

## 它不是

- 不是独立的漏洞扫描器，不内置 CVE 数据库，也不会自动检测或自动修复。
- 不会在后台自动运行检查。连接本身只启动 SSH 登录，不执行远端检查命令。
- 不负责生成 SSH 密钥、端口转发或跳板机。

## 依赖与限制

- Windows 需要系统 OpenSSH 客户端（`ssh.exe`）。
- 原生目录选择器仅在 DSH Desktop（Windows / macOS）可用；纯浏览器环境下「浏览…」会提示改用手动输入路径。
- 一个聊天只跟踪一条由本插件建立的 SSH 连接；同一台主机重新连接成功后，旧连接会被替换（旧聊天中的 SSH 工具随之失效）。
- 文件浏览使用独立的后台 ssh 通道，只支持**密钥认证**的 Linux / Unix 主机；带口令的私钥需先加入 ssh-agent（Windows 需启用「OpenSSH Authentication Agent」服务）。密码认证的主机请在终端中查看文件。
- SFTP 上传沿用密钥认证，需要本机 OpenSSH 的 `sftp` 客户端、远端 SFTP 服务和目标目录的写权限。新文件保护需远端文件系统支持硬链接。巡检快照需要 Linux 的 `/proc`，服务状态由 systemd 提供。
- 在终端里手动输入后，宿主会把该终端交由你控制，插件无法再写入命令；如需让 AI 继续执行，请在面板中重新「连接」。
- 终端连接所用的 ssh 选项要求 OpenSSH 7.6 及以上的客户端（Windows 10 自带的 8.1 也满足）。
- 需要交互式二次验证（如键盘交互 / 2FA）时，请在右侧终端中手动完成。
- 严格主机密钥校验依赖系统 `known_hosts`。
